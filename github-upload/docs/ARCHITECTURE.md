# RTAF Document Assistant — โครงสร้างระบบ (ขั้นที่ 1)

## ขอบเขต MVP รุ่น 0.1
- เอกสารประเภทเดียว: **บันทึกข้อความ**
- ทำงานในเบราว์เซอร์ทั้งหมด ไม่มีเซิร์ฟเวอร์ ไม่เรียก API ภายนอก ไม่โหลดฟอนต์/สคริปต์จากอินเทอร์เน็ต
- เก็บข้อมูลใน Local Storage ของเบราว์เซอร์ (เฉพาะข้อมูลเอกสารทั่วไป ไม่เก็บรหัสผ่าน)

## หลักการออกแบบ
1. **แยกข้อมูลออกจากรูปแบบ** — `DocumentRecord` เก็บเฉพาะข้อมูลที่ผู้ใช้กรอก, `MemoTemplate` เก็บเฉพาะรูปแบบ (ฟอนต์ ระยะขอบ ระยะบรรทัด ตำแหน่งข้อความ ป้ายชื่อ ช่องที่จำเป็น)
2. **แบบจำลองการจัดวางกลาง (Layout model)** — `lib/layout.ts` แปลง (ข้อมูล + แม่แบบ) เป็นรายการย่อหน้า แล้วทั้ง "ตัวอย่างบนจอ" และ "ไฟล์ Word" ใช้ผลลัพธ์เดียวกัน เพื่อให้สองฝั่งตรงกัน
3. **ไม่สมมติว่าเป็นรูปแบบมาตรฐานราชการ** — แม่แบบเริ่มต้นติดป้าย "ยังไม่ได้ตรวจสอบกับระเบียบ" และมีช่อง "แหล่งอ้างอิงรูปแบบ" ให้ผู้ใช้ระบุ
4. **ระบบตรวจสอบแจ้งเตือนเท่านั้น** — ไม่แก้ไขข้อมูลใด ๆ อัตโนมัติ
5. **ไม่มีข้อมูลตัวอย่างในคลังข้อมูลจริง** — ตัวอย่างในหน้าแม่แบบใช้ข้อความ ‹ชื่อช่อง› ที่ไม่ถูกบันทึก

## หน้าจอ (เมนูด้านข้าง)
| เมนู | เส้นทาง | หน้าที่ |
|---|---|---|
| Dashboard | `#/` | จำนวนเอกสารทั้งหมด / ฉบับร่าง / ส่งออกแล้ว, เอกสารที่แก้ไขล่าสุด, ปุ่มสร้างเอกสารใหม่ |
| สร้างเอกสาร | `#/new`, `#/edit/:id` | ซ้าย: แบบฟอร์ม + ผลตรวจสอบ, ขวา: ตัวอย่างเอกสาร; บันทึกฉบับร่าง, ส่งออก Word |
| เอกสารทั้งหมด | `#/documents` | ค้นหาจากเรื่อง/เลขที่ และช่วงวันที่, เปิดแก้ไข, ทำสำเนา, ลบ (ยืนยันก่อน) |
| แม่แบบ | `#/templates` | ดูแม่แบบ, ทำสำเนา, แก้ไข, ลบ, ตั้งเป็นค่าเริ่มต้น |
| ตั้งค่า | `#/settings` | แม่แบบเริ่มต้น, สำรองข้อมูล (.json), นำเข้าข้อมูล, ลบข้อมูลทั้งหมด |

## โครงสร้างโค้ด
```
src/
  types.ts                 ชนิดข้อมูลกลาง
  lib/
    thaiDate.ts            แปลงวันที่เป็นรูปแบบไทย (พ.ศ.)
    templates.ts           แม่แบบเริ่มต้น + normalize
    storage.ts             อ่าน/เขียน Local Storage + จัดการข้อผิดพลาด
    backup.ts              สร้าง/ตรวจไฟล์สำรองข้อมูล
    validation.ts          ระบบตรวจสอบเอกสาร
    layout.ts              แบบจำลองการจัดวาง (ใช้ร่วม preview + docx)
    docxExport.ts          สร้างไฟล์ .docx ด้วยไลบรารี docx
    verifyDocx.ts          เปิดไฟล์ที่สร้างแล้วตรวจโครงสร้างก่อนแจ้งสำเร็จ
  state/AppData.tsx        Context จัดการข้อมูล + การแจ้งเตือน
  components/              Sidebar, MemoForm, PreviewDocument, ValidationPanel, Notices
  pages/                   Dashboard, Editor, DocumentList, Templates, Settings
tests/                     ชุดทดสอบ (Vitest)
scripts/                   สคริปต์ทดสอบส่งออกด้วย Microsoft Word จริง
```

## การส่งออก Word
1. ตรวจเอกสาร → ถ้ามีข้อผิดพลาด ถามยืนยันก่อน
2. สร้างไฟล์ด้วย `docx` (ตั้งฟอนต์ทั้งชุดอักษรละตินและ complex script เพื่อให้ภาษาไทยใช้ฟอนต์/ขนาดที่กำหนด)
3. เปิดไฟล์ที่สร้างด้วย JSZip ตรวจว่ามีส่วนประกอบครบและมีข้อความที่กรอกจริง
4. ผ่านการตรวจจึงส่งให้เบราว์เซอร์ดาวน์โหลดและแจ้งผล

## สิ่งที่ยังไม่อยู่ใน MVP (ไม่มีปุ่มในหน้าจอ)
- นำเข้ารูปแบบจากไฟล์ .docx ต้นฉบับโดยตรง (ปัจจุบันปรับค่าในหน้าแม่แบบให้ตรงกับต้นฉบับ)
- เอกสารประเภทอื่น, ตราครุฑ/โลโก้, การแบ่งหน้าอัตโนมัติในตัวอย่าง
